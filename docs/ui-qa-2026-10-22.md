# Sipli Duo UI verification — 22 October 2026

## Changes

The onboarding bottle fills its available pane while preserving room for the
primary action. Home also uses a larger bottle, constrained by the visible
pane height so the base and streak controls remain visible. Artwork and water
use the same aspect ratio.

On split onboarding the question and bottle share the first pane. Inputs,
helper instructions, the live response, and Continue share the other pane.
Question copy has one shared owner and is rendered once. The weight ruler
shrinks to the answer pane's height so its unit selector stays visible.
Wide question panes place bottle and question side by side. Wide answer panes
also use two columns, including the target controls, schedule, name response,
activity choices, and reminder preview/choices. Narrow panes reflow vertically.

Fold resolution preserves the hinge axis when a reserved region is clipped.
Single-column forms choose the roomier pane before applying the readable-width
cap. Calendars and dashboard cards scroll instead of shrinking their controls.
Side-by-side panes no longer apply an outer vertical clip at the safe-area
boundary. Insights has additional bottom content margins in each scroll pane;
the footer test reaches the heatmap legend and streak-freeze note separately.

Fixed overlapping schedule labels, dial gesture coordinates, narrow weight
layouts, selection padding shifts, wrapping notification choices, keyboard
dismissal, intake confirmation placement, rapid duplicate logging, and paywall
close-button reachability. Achievement celebrations use a native modal so the
Duo's navigation chrome cannot intercept their buttons. The add-drink action
uses an automatically styled native toolbar Button and native sheet.

Added small press feedback, a short tab arrival, numeric transitions, and
onboarding fades. Added movement and delayed entrances respect Reduce Motion.
Tab arrival starts only on the newly visible tab, avoiding animation work on
hidden native navigation stacks.
The existing bottle motion also has a tested simulator reduced-motion path.

The Duo simulator advertised FoundationModels support but trapped during
generation. Simulator builds now use the existing deterministic coaching
fallbacks. Physical-device model behavior is unchanged.

## Boundaries

These checks cover the recorded simulator sizes, poses, states, and text size;
they do not establish that every possible UI state is bug-free. The closed
cover is orientation-locked by iOS. The four native rotations apply to the inner
display. Secondary screens do not have a complete pose × orientation × text-size
matrix. Full VoiceOver, all Dynamic Type sizes/locales, physical-device motion,
HealthKit/weather services, device Apple Intelligence, and real billing remain
separate device/integration checks. No real purchases or external shares were
performed.

## Reproduce

Build the UI-test scheme without regenerating the Xcode project:

```sh
xcodebuild -project WaterQuest.xcodeproj -scheme WaterQuestBottleUI \
  -configuration Debug \
  -destination 'platform=iOS Simulator,id=CDB81C48-A71D-42CA-8320-22F140F31F18' \
  -derivedDataPath /tmp/sipli-duo-build \
  CODE_SIGNING_ALLOWED=NO ONLY_ACTIVE_ARCH=YES build-for-testing
```

With that Duo visible in Device Hub, choose a fresh result-bundle path:

```sh
python3 scripts/run-duo-ui-audit.py \
  --device CDB81C48-A71D-42CA-8320-22F140F31F18 \
  --xctestrun /tmp/sipli-duo-build/Build/Products/WaterQuestBottleUI_iphonesimulator27.2-arm64.xctestrun \
  --result /tmp/sipli-new-audit.xcresult --log /tmp/sipli-new-audit.log \
  --pose partial --appearance dark \
  --tests DuoLayoutTests/testOnboardingAllStepsTabletop DuoLayoutTests/testTabsTabletopFold
```

Use `--pose closed` for the cover: the coordinator tells tests to keep its
portrait orientation instead of injecting sensor rotations into a locked
display. Repeatedly changing that sensor while the cover was locked produced
stale tap coordinates and was rejected as a verification method.
